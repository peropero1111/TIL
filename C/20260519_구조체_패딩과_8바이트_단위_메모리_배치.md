# TIL - 구조체 패딩과 8바이트 단위 메모리 배치

> 원본 파일: `20250519.c`  
> 학습 주제: 구조체(`struct`), `sizeof`, 메모리 정렬, 패딩, 시작 byte 위치

## 오늘 배운 내용

구조체 안의 변수들은 **선언된 순서대로 메모리에 배치**된다.
하지만 자료형마다 정렬 기준이 다르기 때문에, 컴파일러가 중간에 빈 공간을 넣을 수 있다.
이 빈 공간을 **패딩(padding)** 이라고 한다.

이번 예제에서는 `double`이 8 byte 단위로 정렬된다고 보고,
메모리 배치를 **8 byte씩 잘라서** 확인한다.

즉, 아래 표에서 한 줄은 다음 의미를 가진다.

```text
한 줄 = 8 byte = double 1개 크기
```

>  


## 원본 구조체

원본 코드의 구조체는 다음 순서로 선언되어 있다.

```c
struct point
{
    char a;
    char b;
    float c;
    char d;
    double x;
    double y;
    char a1;
} typedef point;
```

그리고 `main()`에서는 구조체 변수 하나의 크기를 출력한다.

```c
int main(void)
{
    point one;
    printf("%lu\n", sizeof(one));
}
```

일반적인 64-bit 환경에서는 다음처럼 생각할 수 있다.

| 자료형 | 크기 | 정렬 기준 |
|---|---:|---:|
| `char` | 1 byte | 1 byte |
| `float` | 4 byte | 4 byte |
| `double` | 8 byte | 8 byte |

## 원래 선언 순서의 메모리 배치

원래 선언 순서는 다음과 같다.

```text
char a → char b → float c → char d → double x → double y → char a1
```

이를 `double` 크기인 **8 byte 단위**로 자르면 다음과 같다.

### 원래 순서: 8B 단위 메모리 그림

| byte 범위 | 1B | 2B | 3B | 4B | 5B | 6B | 7B | 8B |
|---:|---|---|---|---|---|---|---|---|
| `0~7` | `a` | `b` | PAD | PAD | `c` | `c` | `c` | `c` |
| `8~15` | `d` | PAD | PAD | PAD | PAD | PAD | PAD | PAD |
| `16~23` | `x` | `x` | `x` | `x` | `x` | `x` | `x` | `x` |
| `24~31` | `y` | `y` | `y` | `y` | `y` | `y` | `y` | `y` |
| `32~39` | `a1` | PAD | PAD | PAD | PAD | PAD | PAD | PAD |

위 표는 이렇게 읽으면 된다.

```text
왼쪽 byte 범위는 구조체 시작 위치부터의 실제 byte 위치를 나타낸다.
```

예를 들어 `float c`는 `0~7` 줄의 5번째 칸부터 8번째 칸까지 차지한다.
C에서 byte 번호는 0부터 세기 때문에, 전체 구조체 안에서는 byte 위치 `4~7`에 저장된다.

### 원래 순서의 실제 byte 위치

| 멤버 | byte 위치 | 크기 | 설명 |
|---|---:|---:|---|
| `a` | 0 | 1B | 바로 저장 |
| `b` | 1 | 1B | 바로 저장 |
| PAD | 2~3 | 2B | `float c`를 4B 기준에 맞추기 위한 패딩 |
| `c` | 4~7 | 4B | `float` |
| `d` | 8 | 1B | 바로 저장 |
| PAD | 9~15 | 7B | `double x`를 8B 단위에 맞추기 위한 패딩 |
| `x` | 16~23 | 8B | `double` |
| `y` | 24~31 | 8B | `double` |
| `a1` | 32 | 1B | 바로 저장 |
| PAD | 33~39 | 7B | 구조체 전체 크기를 8B 배수로 맞추기 위한 마지막 패딩 |

따라서 원래 순서의 구조체 크기는 다음처럼 계산된다.

```text
실제 데이터: char 4개 + float 1개 + double 2개
          = 4B + 4B + 16B
          = 24B

패딩: 2B + 7B + 7B
    = 16B

전체 크기: 24B + 16B = 40B
```

그래서 원래 구조체에서는 일반적인 64-bit 환경 기준으로 다음처럼 출력될 수 있다.

```text
40
```

## 추가 예제: `int` 멤버를 사용한 구조체

그림의 작은 칸을 원본 코드의 `char`가 아니라 실제 `int`로 보면 다음 구조체처럼 정리할 수 있다.

```c
struct point
{
    int a;
    int b;
    float c;
    int d;
    double x;
    int e;
};
```

> 주의: 같은 C 파일 안에서는 기존 `struct point`와 이름이 겹치므로 둘 중 하나만 사용하거나, 비교용 구조체 이름을 `struct point_int`처럼 바꿔야 한다.

일반적인 64-bit 환경에서 `int`는 4B, `float`은 4B, `double`은 8B라고 보면 된다.

| 자료형 | 크기 | 정렬 기준 |
|---|---:|---:|
| `int` | 4 byte | 4 byte |
| `float` | 4 byte | 4 byte |
| `double` | 8 byte | 8 byte |

선언 순서는 다음과 같다.

```text
int a → int b → float c → int d → double x → int e
```

이를 `double` 크기인 **8 byte 단위**로 자르면 다음과 같다.

### `int` 구조체: 8B 단위 메모리 그림

| byte 범위 | 1B | 2B | 3B | 4B | 5B | 6B | 7B | 8B |
|---:|---|---|---|---|---|---|---|---|
| `0~7` | `a` | `a` | `a` | `a` | `b` | `b` | `b` | `b` |
| `8~15` | `c` | `c` | `c` | `c` | `d` | `d` | `d` | `d` |
| `16~23` | `x` | `x` | `x` | `x` | `x` | `x` | `x` | `x` |
| `24~31` | `e` | `e` | `e` | `e` | PAD | PAD | PAD | PAD |

그림으로 보면 다음과 같다.

```text
8B 블록 0 / 0~7 byte
┌────┬────┬────┬────┬────┬────┬────┬────┐
│ a  │ a  │ a  │ a  │ b  │ b  │ b  │ b  │  int a 4B + int b 4B
└────┴────┴────┴────┴────┴────┴────┴────┘

8B 블록 1 / 8~15 byte
┌────┬────┬────┬────┬────┬────┬────┬────┐
│ c  │ c  │ c  │ c  │ d  │ d  │ d  │ d  │  float c 4B + int d 4B
└────┴────┴────┴────┴────┴────┴────┴────┘

8B 블록 2 / 16~23 byte
┌────┬────┬────┬────┬────┬────┬────┬────┐
│ x  │ x  │ x  │ x  │ x  │ x  │ x  │ x  │  double x = 8B
└────┴────┴────┴────┴────┴────┴────┴────┘

8B 블록 3 / 24~31 byte
┌────┬────┬────┬────┬────┬────┬────┬────┐
│ e  │ e  │ e  │ e  │PAD │PAD │PAD │PAD │  int e 4B + 마지막 패딩 4B
└────┴────┴────┴────┴────┴────┴────┴────┘
```

### `int` 구조체의 실제 byte 위치

| 멤버 | byte 위치 | 크기 | 설명 |
|---|---:|---:|---|
| `a` | 0~3 | 4B | `int` |
| `b` | 4~7 | 4B | `int` |
| `c` | 8~11 | 4B | `float` |
| `d` | 12~15 | 4B | `int` |
| `x` | 16~23 | 8B | `double`, 16번 byte는 이미 8B 정렬에 맞음 |
| `e` | 24~27 | 4B | `int` |
| PAD | 28~31 | 4B | 구조체 전체 크기를 8B 배수로 맞추기 위한 마지막 패딩 |

따라서 이 구조체의 크기는 다음처럼 계산된다.

```text
실제 데이터: int 4개 + float 1개 + double 1개
          = 16B + 4B + 8B
          = 28B

마지막 패딩: 4B

전체 크기: 28B + 4B = 32B
```

그래서 이 `int` 버전 구조체의 `sizeof` 결과는 일반적인 64-bit 환경에서 다음처럼 나올 수 있다.

```text
32
```

즉, 작은 칸이 진짜 `int`라면 24B가 아니라 **32B**가 된다.
`int`는 1B가 아니라 보통 4B이고, 구조체 전체 크기도 가장 큰 정렬 기준인 `double`의 8B 배수로 맞춰지기 때문이다.

## 선언 순서를 바꾼 경우

패딩을 줄이려면 보통 **큰 자료형부터 작은 자료형 순서**로 선언한다.

같은 멤버들을 다음처럼 다시 배치할 수 있다.

```c
typedef struct point_reordered
{
    double x;
    double y;
    float c;
    char a;
    char b;
    char d;
    char a1;
} point_reordered;
```

선언 순서는 다음과 같다.

```text
double x → double y → float c → char a → char b → char d → char a1
```

## 두 번째 그림: 8B 단위로 다시 그린 byte 범위

이미지처럼 `double` 1개의 크기인 **8B 단위**로 자르면 다음과 같다.

| byte 범위 | 1B | 2B | 3B | 4B | 5B | 6B | 7B | 8B |
|---:|---|---|---|---|---|---|---|---|
| `0~7` | `x` | `x` | `x` | `x` | `x` | `x` | `x` | `x` |
| `8~15` | `y` | `y` | `y` | `y` | `y` | `y` | `y` | `y` |
| `16~23` | `c` | `c` | `c` | `c` | `a` | `b` | `d` | `a1` |

그림으로 보면 다음과 같다.

```text
8B 블록 0 / 0~7 byte
┌────┬────┬────┬────┬────┬────┬────┬────┐
│ x  │ x  │ x  │ x  │ x  │ x  │ x  │ x  │  double x = 8B
└────┴────┴────┴────┴────┴────┴────┴────┘

8B 블록 1 / 8~15 byte
┌────┬────┬────┬────┬────┬────┬────┬────┐
│ y  │ y  │ y  │ y  │ y  │ y  │ y  │ y  │  double y = 8B
└────┴────┴────┴────┴────┴────┴────┴────┘

8B 블록 2 / 16~23 byte
┌────┬────┬────┬────┬────┬────┬────┬────┐
│ c  │ c  │ c  │ c  │ a  │ b  │ d  │ a1 │  float c 4B + char 4개
└────┴────┴────┴────┴────┴────┴────┴────┘
```

이 경우에는 8B 단위로 잘랐을 때 딱 3줄이 된다.

```text
8B × 3줄 = 24B
```

따라서 재배치한 구조체의 `sizeof` 결과는 일반적인 64-bit 환경에서 다음처럼 나올 수 있다.

```text
24
```

## 왜 24 byte가 되는가?

재배치한 구조체는 실제 데이터가 24 byte이고, 중간 패딩이 필요하지 않다.

```text
double x = 8B
double y = 8B
float c  = 4B
char a   = 1B
char b   = 1B
char d   = 1B
char a1  = 1B
----------------
합계      = 24B
```

또한 구조체 전체 크기는 가장 큰 정렬 기준인 `double`의 8B 배수가 되어야 한다.
그런데 `24`는 이미 8의 배수이다.

```text
24 % 8 == 0
```

그래서 끝에 추가 패딩도 붙지 않는다.

## 원래 순서와 재배치 순서 비교

| 구분 | 선언 순서 | 패딩 | `sizeof` 결과 |
|---|---|---:|---:|
| 원래 구조체 | `char`, `char`, `float`, `char`, `double`, `double`, `char` | 16B | 40B |
| 재배치 구조체 | `double`, `double`, `float`, `char`, `char`, `char`, `char` | 0B | 24B |

정확히 말하면, **변수에 저장되는 값 자체가 바뀌는 것은 아니다.**
달라지는 것은 다음 두 가지이다.

1. 각 멤버가 구조체 안에서 시작하는 byte 위치
2. 패딩의 개수와 위치 때문에 달라지는 `sizeof` 결과

## `offsetof`로 시작 byte 위치 확인하기

`offsetof`를 사용하면 멤버가 구조체 안에서 몇 번째 byte부터 시작하는지 확인할 수 있다. 여기서 확인하는 값은 “구조체 시작 지점으로부터 떨어진 byte 수”이다.

```c
#include <stdio.h>
#include <stddef.h>

struct point
{
    char a;
    char b;
    float c;
    char d;
    double x;
    double y;
    char a1;
};

typedef struct point_reordered
{
    double x;
    double y;
    float c;
    char a;
    char b;
    char d;
    char a1;
} point_reordered;

int main(void)
{
    printf("original size: %zu\n", sizeof(struct point));
    printf("a  start byte: %zu\n", offsetof(struct point, a));
    printf("b  start byte: %zu\n", offsetof(struct point, b));
    printf("c  start byte: %zu\n", offsetof(struct point, c));
    printf("d  start byte: %zu\n", offsetof(struct point, d));
    printf("x  start byte: %zu\n", offsetof(struct point, x));
    printf("y  start byte: %zu\n", offsetof(struct point, y));
    printf("a1 start byte: %zu\n", offsetof(struct point, a1));

    printf("\nreordered size: %zu\n", sizeof(point_reordered));
    printf("x  start byte: %zu\n", offsetof(point_reordered, x));
    printf("y  start byte: %zu\n", offsetof(point_reordered, y));
    printf("c  start byte: %zu\n", offsetof(point_reordered, c));
    printf("a  start byte: %zu\n", offsetof(point_reordered, a));
    printf("b  start byte: %zu\n", offsetof(point_reordered, b));
    printf("d  start byte: %zu\n", offsetof(point_reordered, d));
    printf("a1 start byte: %zu\n", offsetof(point_reordered, a1));

    return 0;
}
```

일반적인 64-bit 환경에서는 다음과 비슷하게 출력될 수 있다.

```text
original size: 40
a  start byte: 0
b  start byte: 1
c  start byte: 4
d  start byte: 8
x  start byte: 16
y  start byte: 24
a1 start byte: 32

reordered size: 24
x  start byte: 0
y  start byte: 8
c  start byte: 16
a  start byte: 20
b  start byte: 21
d  start byte: 22
a1 start byte: 23
```

## 오늘의 정리

구조체의 멤버는 선언된 순서대로 저장된다.
하지만 `double`은 보통 8B 정렬, `float`은 4B 정렬이 필요하므로,
선언 순서에 따라 중간에 패딩이 생길 수 있다.

이번 예제에서 원래 순서는 다음처럼 8B 블록 5개가 필요하다.

```text
0~7    : a, b, PAD, PAD, c, c, c, c
8~15   : d, PAD, PAD, PAD, PAD, PAD, PAD, PAD
16~23  : x, x, x, x, x, x, x, x
24~31  : y, y, y, y, y, y, y, y
32~39  : a1, PAD, PAD, PAD, PAD, PAD, PAD, PAD
```

그래서 `sizeof`가 40B가 된다.

반대로 큰 자료형부터 배치하면 다음처럼 8B 블록 3개로 끝난다.

```text
0~7    : x, x, x, x, x, x, x, x
8~15   : y, y, y, y, y, y, y, y
16~23  : c, c, c, c, a, b, d, a1
```

그래서 `sizeof`가 24B가 된다.

그냥 쉽게 double을 기준으로 하여서 위와 에 있는 double이 아닌 변수들을 double에 맞춘 다음 나온 줄의 총합 ( 중간 중간에 pad 포함 할 수 있음 ) X 8 ( double ) 을 하면 된다.
